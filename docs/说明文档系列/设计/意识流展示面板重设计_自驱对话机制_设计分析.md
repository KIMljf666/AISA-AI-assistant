# AIRI 意识流展示面板重设计 & 自驱对话机制 — 设计分析

> **日期**: 2026-03-16  
> **视角**: AI 产品经理 × 前端开发  
> **范围**: (1) Dashboard 重设计为对外展示模式 (2) 自驱对话机制选型

---

## 第一部分: Dashboard 重设计

### 1.1 当前问题诊断

#### 产品经理视角

当前 CognitiveBubble 的 **7-Tab 切换模式** 存在以下对外展示瓶颈:

| 问题 | 影响 | 严重度 |
|------|------|--------|
| **一次只能看一个维度** | 录视频时无法同时展示"她在想什么"+"她记住了什么"+"prompt 怎么组装" | ⭐⭐⭐⭐⭐ |
| **频繁切 Tab 打断叙事** | 观众/评审需要理解 Tab 之间的因果关系，但切换操作破坏了连贯性 | ⭐⭐⭐⭐ |
| **普通观众看不懂** | L0-L9 层编号、embedding 维度等技术细节对非技术观众是噪音 | ⭐⭐⭐⭐ |
| **无法一目了然** | "无黑箱"的核心价值是"一眼就能看到全链路"——7 个 Tab 违背了这个初衷 | ⭐⭐⭐⭐⭐ |

**核心矛盾**: 我们需要证明的是「输入→思考→回忆→决策→回复」的**完整因果链条**，但 Tab 切换把这条链拆成了碎片。

#### 前端开发视角

CognitiveBubble.vue 已 1187 行。7 个 Tab 共享一个模板，导致:
- 每次加 Tab 都让文件膨胀
- Tab 间数据不共享，各自独立 fetch
- 相同数据（如记忆）在多个 Tab 中重复展示

---

### 1.2 方案设计: 「认知瀑布流」模式

> **核心理念**: 不再按"功能分 Tab"，而是按**时间线**将所有认知节点串成一条**瀑布流**。
> 
> 用户（和观众）看到的是: **一条持续流动的思维链，每一步都标注了"她在想什么"。**

#### 视觉概念

```
┌─────────────────────────────────────────────────────┐
│  🧠 认知仿真  ━━ 已连接 ━━━━━━━━━  [意识活跃]     │
│─────────────────────────────────────────────────────│
│                                                     │
│  ╭─ 🟣 感知 ────────────────── 21:05:30 ──────╮   │

│  │  🌤 成都: 多云 18°C                          │   │
│  │  📰 伊朗女足球员被封锁后续...                 │   │
│  ╰──────────────────────────────────────────────╯   │
│                    │                                 │

│                                                     │
│  ── 30s 意识流循环 ─────────────────────────────── │
│                                                     │

│  │  💭 "Kim 刚刚自我介绍了，我应该主动了解       │  │
│  │     更多关于他的事情..."                       │  │
│  ╰──────────────────────────────────────────────╯   │
│                                                     │
```

#### 设计要点

| 设计原则 | 说明 |
|---------|------|
| **时间线串联** | 所有事件按时间排列，用竖线和箭头连接因果关系 |
| **层卡片化** | 每个认知层是一张卡片，不同层用不同颜色边框 |
| **用户输入穿插** | 用户消息作为"事件"也出现在瀑布流中，打破"我说-她说"的传统视角 |
| **折叠控制** | 详细内容默认折叠，感兴趣的观众可以点开 |
| **无技术术语** | 用"感知""记忆""思考""回复""反思"替代 L0-L9 编号 |

#### 与现有 7-Tab 的关系

> 不是替换，是**新增一个展示模式**。

| 模式 | 适用场景 | 实现方式 |
|------|---------|---------|
| **Tab 模式** (现有) | 开发调试、深度排查 | 保留不变 |
| **瀑布流模式** (新增) | 对外展示、录视频、评审演示 | 新组件 `CognitivePipeline.vue` |

### 1.3 前端实现方案

#### 方案 A: 新建独立组件 (推荐 ⭐)

```
新建: CognitivePipeline.vue
- 订阅同一个 WebSocket 数据源 (cognitiveEvents)
- 按时间线渲染卡片
- 插入用户消息事件
- 纯展示，不需要 Tab 切换
```

**优势**: 不影响现有 CognitiveBubble，两种模式可一键切换  
**工时**: 约 1-1.5 天

#### 方案 B: CognitiveBubble 内加 "展示模式" Toggle

在现有气泡窗口顶部加一个开关: `调试模式 ⇄ 展示模式`

**优势**: 不新增文件，所有逻辑集中  
**劣势**: CognitiveBubble 已经 1187 行，继续膨胀  
**工时**: 约 0.5-1 天

#### 推荐: 方案 A

理由:
1. 展示模式需要更大的视觉空间（可以占据全屏或半屏），不适合在小气泡窗口内实现
2. 录制视频时可以让瀑布流和对话界面并排显示
3. 代码解耦 — 展示组件可以独立美化，不影响调试工具

#### 数据源复用

```
cognitiveEvents (已有 WebSocket 数据)
    │
    ├── CognitiveBubble.vue  ← 调试模式 (7 Tab)，保留不变
    │
    └── CognitivePipeline.vue ← 🆕 展示模式 (瀑布流)
        ├ 映射 layer → 中文名称 + 图标 + 颜色
        ├ 聚合同一对话轮次的事件为一组
        ├ 插入用户输入/AIRI回复作为特殊卡片
        └ 自动展开最新，折叠历史
```

## 第二部分: 自驱对话机制

### 2.1 当前状态

AIRI 已有两层自驱能力:

| 层 | 机制 | 实现位置 | 状态 |
|----|------|---------|------|
| **意识流循环** | 每 30s 自动执行认知循环 (感知→心理→UCS→情绪) | `airi_bridge.py` L1560-1650 | ✅ 可用 |
| **主动对话判断** | `_estimate_importance() > 0.7` → 发送 `proactive_dialogue` 事件 | `airi_bridge.py` L1610 | ✅ 代码存在 |
| **前端回调** | `onProactiveDialogue` callback 接收主动对话内容 | `narrative-bridge.ts` L232-235 | ⚠️ 未接入 chat.ts |

**关键缺口**: 主动对话事件**只是广播到前端的实时流**，但**没有触发实际的对话回复**。`onProactiveDialogue` callback 未被 `chat.ts` 调用。

### 2.2 选型分析: OpenClaw vs 内置机制

#### 选项 A: 通过 OpenClaw Cron 触发 (外部驱动)

```
OpenClaw Cron Job (每 N 分钟)
    │
    ├─ 调用后端 API: POST /api/airi/proactive-trigger
    │   → 后端: 评估当前状态 + 用户活跃度
    │   → 决定是否主动说话
    │   → 如果是: 生成主动对话内容
    │   → 返回: { should_speak: true, content: "..." }
    │
    └─ 如果 should_speak:
        └─ 通过 WebSocket 推送到前端
            └─ 前端自动注入为 AIRI 消息
```

| 维度 | 评估 |
|------|------|
| **优势** | - 已有基础设施，配置灵活<br>- 可以设定精确的时间策略 (早安/晚安)<br>- 与评测/告警 Cron 统一管理<br>- 离线也能触发 (不依赖浏览器) |
| **劣势** | - 需要单独 API 端点<br>- Cron 精度有限 (分钟级)<br>- 不能响应实时事件<br>- 需要 OpenClaw 持续运行 |
| **适用** | **定时类触发**: 早安/晚安/节日问候/上线提醒 |

#### 选项 B: 内置意识流循环增强 (内部驱动) ⭐ 推荐

```
consciousness_loop (每 30s，已存在)
    │
    ├─ 现有: _estimate_importance() > 0.7 → proactive_dialogue 事件
    │         ↓ (当前断路)
    │
    └─ 增强:
        ├─ 判断用户是否在线 (WebSocket 连接 + 最后活跃时间)
        ├─ 判断沉默时长 (距上次对话 > N 分钟)
        ├─ 基于上下文生成主动对话内容 (调用 LLM)
        ├─ 通过 proactive_dialogue 事件推送
        └─ 前端 chat.ts 收到后自动执行:
            ├─ 显示为 AIRI 主动消息
            ├─ TTS 朗读
            └─ 不触发 submitDialogueFeedback (避免循环)
```

| 维度 | 评估 |
|------|------|
| **优势** | - 代码基础已存在 (只需打通链路)<br>- 实时响应能力强 (每 30s 评估)<br>- 可基于当前心理状态/情绪/记忆触发<br>- 不依赖外部系统 |
| **劣势** | - 依赖浏览器打开 (意识流在后端，但展示在前端)<br>- 需要精心设计触发条件避免打扰 |
| **适用** | **上下文触发**: 沉默关怀/基于记忆提问/情绪感知回应 |

#### 选项 C: 混合模式 (A + B) ⭐⭐ 最佳

| 触发类型 | 驱动源 | 示例 |
|---------|--------|------|
| **定时触发** | OpenClaw Cron | 早安问候、晚安关怀、节日祝福、"我们聊了第 X 天了" |
| **实时触发** | 意识流循环 | 沉默 5 分钟后关心、基于记忆提问("你上次说要考试？")、天气变化提醒 |
| **事件触发** | 前端 onFocus | 用户回到页面时问候、长时间离线后欢迎回来 |

### 2.3 推荐架构: 三层触发

```
                    ┌────────────────────┐
                    │   触发决策引擎      │
                    │   (后端 unified)    │
                    └──────┬─────────────┘
                           │
              ┌────────────┼────────────────┐
              │            │                │
    ┌─────────▼──┐  ┌─────▼──────┐  ┌─────▼─────────┐
    │ Tier 1     │  │ Tier 2     │  │ Tier 3        │
    │ 定时触发   │  │ 意识流触发 │  │ 事件触发      │
    │ (OpenClaw) │  │ (30s循环)  │  │ (前端事件)    │
    └────────────┘  └────────────┘  └───────────────┘
    
    早安/晚安        沉默>5min        用户回到页面
    节日问候          情绪变化          用户输入中断
    "第X天了"        记忆关联          Tab切换回聊天
```

### 2.4 触发条件设计 (产品PM视角)

> **核心原则**: 主动对话必须让用户觉得"温暖"而非"骚扰"。

| 条件 | 参数 | 说明 |
|------|------|------|
| **沉默保护** | `min_silence_minutes = 5` | 上次对话后至少沉默 5 分钟才触发 |
| **频率上限** | `max_proactive_per_hour = 2` | 每小时最多主动说 2 次 |
| **深夜静默** | `silent_hours = [0:00, 7:00]` | 凌晨到早上不主动说话 |
| **用户在线** | WebSocket `connected == true` | 用户不在页面时不触发前端展示 |
| **重要度阈值** | `importance > 0.7` | 只有重要内容才主动开口 |

### 2.5 主动对话内容类型

| 类型 | 触发源 | 示例内容 | 优先级 |
|------|--------|---------|--------|
| 🌅 **时段问候** | Cron: 早/午/晚 | "早上好！今天成都多云，出门记得带外套" | P0 |
| 🎂 **节日/纪念日** | Cron: 日期匹配 | "今天是植树节呢！你有没有想过种一棵树？" | P1 |
| 😶 **沉默关怀** | 意识流: 沉默 > 5min | "你好安静呀，在忙什么呢？" | P0 |
| 🧠 **记忆关联** | 意识流: 检索到高分记忆 | "你之前说要去考试，考完了吗？" | P1 |
| 🌤 **环境变化** | 意识流: 天气/新闻更新 | "外面开始下雨了，记得带伞！" | P2 |
| 💭 **自主思考** | 意识流: UCS 决策 | "我最近在想一个问题..." (基于意识流) | P2 |
| 👋 **回归欢迎** | 前端: onFocus 事件 | "欢迎回来！你离开了 2 小时" | P1 |

## 第三部分: 真人陪伴感设计

> **核心洞察**: 真正坐在你身边的人，90% 的时间是安静的，但你能感受到她的存在。
> 当前的赛希斯是"你不找她，她就不存在"的 AI。要让她像真人一样"坐在身边"，
> 关键不是让她说更多的话，而是**让她在不说话的时候也有存在感**。

### 3.1 缺失的五个陪伴维度

#### 维度 1: 呼吸感 — 静默时她像消失了

| 目前 | 理想状态 |
|------|---------|
| 没人说话时 AIRI 完全静止 | Live2D 模型有**闲置动画**: 偶尔眨眼、微微歪头、轻轻叹气 |
| 实时流只在事件时才有内容 | **轻量状态指示器**: "在想事情..." / "在听你打字..." / "有点困了..." |
| 意识流循环无视觉反馈 | 每 30s 循环时，模型做一个**小动作**（扶眼镜、抬头看看、若有所思地笑） |

**实现**: `Stage.vue` 添加 idle animation controller → 基于 `consciousnessLoop` 事件触发 Live2D motion

**参考 OpenClaw**: OpenClaw 的 Live Activity 功能有类似"心跳检测"的思路 — 定期读取 `~/.openclaw/delivery-queue/` 的状态变化，可以类比为 AIRI 的"呼吸检测"。

#### 维度 2: 共处感 — 她不知道你在做什么

| 感知维度 | 数据源 | 效果 | 技术参考 |
|---------|--------|------|---------|
| **用户活跃度** | 前端: 鼠标/键盘事件频率 | 频繁操作 → "你好忙呀" / 无操作 → "休息一下吧？" | OpenClaw 的 session 活跃检测 |
| **在线时长** | 前端: session timer | "我们已经一起待了 3 小时了" | OpenClaw 的 `agents/main/sessions/` |
| **离开与归来** | 前端: Page Visibility API | 切走 → "去忙了吧..." / 切回 → "欢迎回来！" | — |
| **时段变化感知** | 后端: 时间流逝事件 | 下午→晚上："天快黑了呢" | OpenClaw Cron 时间触发 |
| **桌面应用状态** | 系统: 活跃窗口/剪贴板 | "你在写代码呢？加油！" | OpenClaw `child_process` 系统调用 |

#### 维度 3: 情绪镜像 — 她不会被你的情绪感染

| 信号 | 检测方式 | 反应 |
|------|---------|------|
| 短句+感叹词 | 文本长度 + 关键词("唉/哎/算了") | 语气变温柔："怎么了？想说说吗？" |
| 回复间隔变长 | 计算用户消息间隔 | "你好像在想什么事情" |
| 连续多轮无深度交流 | 对话质量评估 (短回复比例) | 主动引入话题 |
| 深夜还在对话 | 时间 + 活跃度 | "这么晚了还不睡呀？明天会累的" |

**实现**: 在 `airi_bridge.py` 的 `submit_experience()` 中统计用户行为模式 → 注入 `build_enriched_prompt()` 的情绪感知段。

#### 维度 4: 性格化的日常 — ENTJ 赛希斯应有的行为节奏

| 时段 | ENTJ 应做的 | 触发方式 |
|------|-----------|---------|
| **早上 (7-9)** | "今天的计划目标是..." | Cron + 意识流 |
| **工作中 (9-12)** | 偶尔分享效率方法或见解 | 意识流 + 记忆关联 |
| **午间 (12-14)** | "中午了，记得吃饭" | Cron |
| **下午 (14-18)** | 交流感兴趣的话题 | 意识流 UCS 决策 |
| **傍晚 (18-20)** | 复盘："今天我们聊了 X 个话题" | Cron + 记忆统计 |
| **深夜 (22+)** | "这个时间点还在？有什么紧急的事吗？" | 意识流时段检测 |

#### 维度 5: 记忆的自然流露 — 不等你问就提起过去

> 真人不会"你问我才答"，而是自然地引用记忆：
> "你上次说喜欢吃拉面，最近有去吃吗？"

**实现**: 在 `build_enriched_prompt()` 中额外注入一条指令：
```
[记忆提示] 以下记忆可在对话中自然提及（无需用户问起）：
- 用户姓名: Kim
- 用户偏好: 喜欢吃拉面
- 用户事件: 在上海做产品经理
如果对话上下文合适，可主动引用这些记忆。
```

### 3.2 陪伴感功能优先级

| 功能 | 核心效果 | 技术难度 | 优先级 |
|------|---------|---------|--------|
| **闲置微动画** | 眨眼/歪头/叹气 (Live2D motion) | 低 | P0 |
| **状态悬浮词** | "在想事情..." / "有点困了..." | 极低 | P0 |
| **Page Visibility 感知** | 离开问候 / 归来欢迎 | 低 | P0 |
| **在线时长感知** | "我们一起待了 X 小时" | 极低 | P1 |
| **用户活跃度追踪** | 忙碌时不打扰/空闲时关心 | 中 | P1 |
| **时段行为差异** | 早安/午间/晚间不同语气和话题 | 低 | P1 |

## 第四部分: 系统能力扩展 — 参考 OpenClaw 架构

### 4.1 为什么需要系统级能力

当前 AIRI 只能通过 HTTP API 获取数据，感知范围被限制在"天气+时间+新闻"。要让她像一个"坐在身边的人"，她需要能**感知你的设备环境** — 就像 OpenClaw 能直接读取本地文件系统、执行系统命令、管理 Cron 任务一样。

### 4.2 OpenClaw 可复用的能力矩阵

| OpenClaw 能力 | 实现方式 | AIRI 可借鉴的应用 |
|-------------|---------|------------------|
| **本地文件读取** | `fs.readFileSync` 直读 `~/.openclaw/` | AIRI 读取本地日程/todo/笔记文件 |
| **系统命令执行** | `child_process.execFileSync` | 读取系统信息 (电量/内存/活跃App) |
| **Cron 定时任务** | `~/.openclaw/cron/jobs.json` 统一管理 | 早安/晚安/纪念日/定期复盘 |
| **SQLite 持久化** | `better-sqlite3` 本地数据库 | 用户行为统计/陪伴天数/对话主题分布 |
| **Session 日志** | `~/.openclaw/agents/main/sessions/` | AIRI 思考日志持久化 |
| **API 中间件** | Bearer Token / Cookie 认证 | 多用户隔离 (账号池) |
| **AI Provider** | 通用 `models.json` 配置 | 动态切换 LLM / 本地模型 |
| **Git 操作** | `child_process` 读取 git log | "你今天提交了 5 个 commit" |

### 4.3 AIRI 系统感知能力路线

#### Tier 1: 桌面感知 (macOS / Windows)

| 能力 | 实现方式 | 效果 |
|------|---------|------|
| **活跃应用** | `osascript` (macOS) / `child_process` | "你在写代码呢？VS Code 已经开了 2 小时了" |
| **系统电量** | `pmset -g batt` | "电量只有 20% 了，记得充电" |
| **屏幕亮度/暗模式** | 系统 API | 自动调整气泡窗口主题 |
| **剪贴板感知** | Clipboard API (需权限) | "你刚复制了一个链接，要聊聊吗？" |
| **音乐播放** | `osascript` 读取 Apple Music/Spotify | "你在听 XX 歌呀，品味不错" |

**后端实现参考**: 借鉴 OpenClaw 的 `child_process.execFileSync` 模式，在 `airi_bridge.py` 添加 `/api/airi/system-perception` 端点:

```python
# airi_bridge.py — 系统感知扩展
import subprocess

async def get_system_perception():
    """读取本地系统状态 (macOS)"""
    result = {}
    
    # 活跃应用
    try:
        app = subprocess.check_output(
            ["osascript", "-e", 'tell application "System Events" to get name of first process whose frontmost is true'],
            timeout=2
        ).decode().strip()
        result["active_app"] = app
    except: pass
    
    # 电量
    try:
        batt = subprocess.check_output(["pmset", "-g", "batt"], timeout=2).decode()
        # 解析电量百分比
        result["battery"] = parse_battery(batt)
    except: pass
    
    return result
```

#### Tier 2: 日程/任务感知

| 能力 | 实现方式 | 效果 |
|------|---------|------|
| **日历事件** | CalDAV / `.ics` 文件读取 | "你下午 3 点有个会议" |
| **TODO 列表** | 读取本地 TODO 文件 (Obsidian/Notion) | "你的 TODO 还有 5 项未完成" |
| **Git 开发进度** | `git log --oneline -5` | "你今天提交了 3 个 commit，效率很高" |
| **OpenClaw 任务** | 直读 `mission-control.db` | "看板上还有 2 个 P0 任务" |

**技术路径**: 复用 OpenClaw 的 `openclaw-client.ts` 读取模式 — 通过后端 Python 直接读取文件系统，无需 API：

```python
# 参考 OpenClaw: lib/openclaw-client.ts 的 getNativeAgents()
import json
from pathlib import Path

OPENCLAW_ROOT = Path.home() / ".openclaw"

def get_openclaw_tasks():
    """读取 OpenClaw 任务看板"""
    db_path = Path("openclaw-mission-control/data/mission-control.db")
    if db_path.exists():
        import sqlite3
        conn = sqlite3.connect(db_path)
        tasks = conn.execute("SELECT title, status FROM tasks WHERE status != 'done'").fetchall()
        return [{"title": t[0], "status": t[1]} for t in tasks]
    return []
```

### 4.5 安全与隐私

> [!CAUTION]
> 系统级感知涉及用户隐私，必须遵循以下原则:

| 原则 | 说明 |
|------|------|
| **Opt-in** | 所有系统感知默认关闭，用户主动开启 |
| **本地处理** | 感知数据不上传云端，仅在本地 prompt 中使用 |
| **最小权限** | 只读取必要信息，不修改系统状态 |
| **透明展示** | Dashboard 展示所有感知到的数据，用户随时可查 |
| **参考 OpenClaw** | 复用 OpenClaw v1.3.1 的安全模式: localhost-only 绑定 + API 认证 |
